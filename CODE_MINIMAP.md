## src/
- `root.zig` — package root for the pure Zig library, re-exporting the core `src/lib` modules plus the C-FFI module for test discovery
- `capi_root.zig` — `libjxl`-shaped public C API layer. Decode-side, it exports the existing `JxlDecoder` compatibility slice (`JxlSignatureCheck`, `JxlDecoder*` create/input/basic-info/output/decode flow) by reusing the Zig decode pipeline and converting into caller-owned interleaved buffers, including tested `UINT8` fast paths for RGB/gray output, correct 8-bit scaling from higher source bit depths, `JxlDecoderGetExtraChannelInfo`, `JxlDecoderGetExtraChannelName`, `JxlDecoderGetColorAsEncodedProfile`, and now animated frame iteration plus first control APIs: repeated `JXL_DEC_FRAME` / `JXL_DEC_FULL_IMAGE` events, `JxlDecoderGetFrameHeader` / `JxlDecoderGetFrameName`, `JxlDecoderRewind`, `JxlDecoderSkipFrames`, and `JxlDecoderSkipCurrentFrame`, so external C and CLI smokes can inspect parsed structured color metadata, frame timing, skipping semantics, and replayed image-output behavior directly. `resetFrameIteration(...)` now also clears the caller-owned output-buffer pointer, which fixes a real rewind bug where the decoder could skip `JXL_DEC_NEED_IMAGE_OUT_BUFFER` on replay and write into freed memory. Encode-side, it now exposes a wider narrow `JxlEncoder` surface: basic-info/color/add-frame/close/process-output still wrap the pure Zig `enc_api` codestream builder, but the structured-color adapter is no longer limited to `sRGB`/`linear sRGB`; it now accepts standard RGB white points (`D65`, `E`, `DCI`), primaries (`sRGB`, `P3`, `BT.2100`), and the standard non-gamma transfer-function enums (`709`, `linear`, `sRGB`, `PQ`, `DCI`, `HLG`) before handing them to the pure Zig encoder core. The C API also stages one or more uint8 sidecar extra channels through `JxlEncoderInitExtraChannelInfo`, `JxlEncoderSetExtraChannelInfo`, `JxlEncoderSetExtraChannelName`, and `JxlEncoderSetExtraChannelBuffer`, carries `JxlFrameHeader` / `JxlEncoderSetFrameHeader` timing metadata, and now supports real multi-frame animation queueing through repeated `JxlEncoderAddImageFrame(...)` plus `JxlEncoderCloseFrames(...)`. When `alpha_bits != 0`, public extra index `0` can now be satisfied either by an interleaved alpha plane supplied via `JxlEncoderAddImageFrame` or by a staged alpha buffer supplied through `JxlEncoderSetExtraChannelBuffer`, and callers may now also set explicit alpha info/name there as long as it matches the declared `JxlBasicInfo` alpha shape, including the first subsampled alpha form (`dim_shift = 1`) as long as the alpha is staged rather than interleaved. Multi-frame queueing now carries staged sidecar extras too, so animated public encode can preserve per-frame `selection_mask`, `depth`, and the same other staged plain/conditional extra metadata that the static path already knows about, as long as the per-frame metadata shape matches. Ambiguous or incompatible inputs like “interleaved alpha plus staged alpha” or “interleaved alpha plus alpha dim_shift != 0” are still rejected explicitly. Final staging now goes through `prepareSimplePackedInput` and `prepareQueuedPackedInput` before codestream assembly inside `JxlEncoderProcessOutput`
- `src/cli/djxlz_root.zig` / `src/cli/djxlz.c` — C CLI entrypoint and implementation for `djxlz`, which dogfoods the public `JxlDecoder` API exclusively. It still writes PPM/PGM/PAM for the static-image path, and now also has a separate GIF export path for still or animated JXL: it subscribes to `JXL_DEC_BASIC_INFO | JXL_DEC_FRAME | JXL_DEC_FULL_IMAGE`, reuses one coalesced image-out buffer per displayed frame, preserves loop count plus per-frame delays from `JxlBasicInfo.animation` / `JxlFrameHeader`, and emits a narrow deterministic per-frame RGB332 GIF with binary transparency through `giflib`
- `src/cli/cjxlz_root.zig` / `src/cli/cjxlz.c` — C CLI entrypoint and implementation for `cjxlz`, which dogfoods the public `JxlEncoder` API exclusively, keeps all parsing/I/O in C, and now accepts native-build GIF and PNG input in addition to raw binary `P5`/`P6` and narrow `P7` PAM (`GRAYSCALE`, `RGB`, `GRAYSCALE_ALPHA`, `RGB_ALPHA`). The CLI decodes PNGs fully in C using `libpng` from memory buffers before passing plain interleaved pixels into the Zig encoder core, and it reuses that same memory-backed decoder for grayscale PNG sidecar extras. The new GIF path also stays entirely in C: it uses `giflib` with a memory-backed reader, coalesces each GIF frame onto a full RGBA canvas while preserving loop count, frame delays, transparency, and disposal behavior, then feeds those full-size frames through repeated public `JxlEncoderAddImageFrame(...)` plus `JxlEncoderCloseFrames(...)`. The plain sidecar forms still accept optional subsampling as `TYPE:SHIFT` (`selection_mask[:SHIFT]`, `depth[:SHIFT]`, `black[:SHIFT]`, `thermal[:SHIFT]`, `optional[:SHIFT]`), and staged alpha is now exposed as `--extra alpha[:SHIFT] PATH`, so the CLI can dogfood both full-size and subsampled staged alpha through the same public encoder API. `--premultiplied-alpha` / `--associated-alpha` mark any supplied alpha channel as associated, `--alpha-name NAME` now dogfoods explicit alpha metadata on top of either interleaved or staged alpha, and the parameterized conditional forms include both `spot_color:R,G,B,S PATH` and `cfa:N PATH`. The CLI also now exposes richer structured-color and metadata flags from the public surface: `--white-point`, `--primaries`, `--transfer-function`, `--linear-srgb`, `--rendering-intent`, `--intensity-target`, `--min-nits`, `--relative-to-max-display`, `--linear-below`, `--orientation`, and `--intrinsic-size`, plus the animation flags `--animation-tps`, `--animation-loops`, `--frame-duration`, and `--frame-timecode`. GIF currently targets the simpler repeated-main-image animation surface only: it does not yet combine GIF input with staged sidecar extras or public decoder-side frame iteration

- `byte_order.zig` — Endian load/store for 16/32/64-bit ints and floats via std.mem
- `random.zig` — Xorshift128+ PRNG matching C++ jxl::Rng exactly
- `rect.zig` — Rect type for rectangular image regions with intersection/translate/shift
- `float.zig` — IEEE 754 float16 to f32 conversion
