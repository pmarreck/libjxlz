# Orientation controls

The public decoder applies the codestream orientation by default.
`JxlDecoderSetKeepOrientation(..., JXL_TRUE)` preserves the coded orientation
and pixel order. Internal frame dimensions remain in codestream order; public
metadata and output buffer sizing account for the selected orientation.

`tests/unit/orientation_oracle.cc` uses upstream libjxl to encode eight 3x2
RGB streams, then decode every orientation with the keep flag off and on.
The retained records cover BasicInfo, frame dimensions with coalescing on/off,
8-bit RGB pixels, aligned rows, and big-endian 16-bit RGBA output. The generator
also writes headers declaring actual 3x2 previews and inserts the encoded frame
body twice. Upstream decodes both the preview and main image and supplies the
expected preview bytes for every orientation/keep combination.

`tests/unit/orientation_crop_oracle.cc` uses the upstream public encoder to
create 16 two-frame streams. They cover all eight orientations with positive
and negative crop origins. Upstream decodes 32 keep-flag combinations with
coalescing disabled and records each frame's dimensions, crop offsets and
pixels. The native tests compare all 64 frame headers and pixel buffers.

The two orientation/intrinsic CLI smokes now expect default reorientation.
Their 2x2 pixel order was also measured with upstream djxl on the native
encoder's orientation-6 output.

The two generators write `src/capi/orientation_fixture.zig` and
`src/capi/orientation_crop_fixture.zig`. Run them against the same upstream
build used for the other retained codec controls. The first needs the source
root, `third_party/highway`, `lib/include`, the build root and its `lib/include`
on the include path; the cropped generator needs only the public source and
build include directories. Both link libjxl, libjxl_cms, Highway, Brotli and
lcms2. Retain the generated bytes and generators together.

Native checks additionally preserve row padding and a byte beyond the caller's
buffer. Allocation injection checks the rotation buffer on success and failure.
Identity orientation uses the direct writer; other orientations pack a temporary
buffer, then copy whole pixels into the destination. This adds one temporary
pixel buffer and one copy for those orientations. No timing claim is made here.

These controls use lossless Modular RGB inputs. Existing output-format tests
cover other conversion paths; this matrix does not establish every combination
of orientation, encoding, floating samples and extra-channel effects.
